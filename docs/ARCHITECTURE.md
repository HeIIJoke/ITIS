# Архитектура сайта кафедры 

Документ отвечает на вопросы «почему так» и «куда класть код».
Кратко: **FastAPI (API) + статичный SPA-фронтенд + pytest**, всё запускается
одной командой и упаковывается в один docker-образ.

---

## 1. Почему такой стек

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **FastAPI + ванильный JS (наш выбор)** | нет сборки, видно каждый инструмент, легко писать тесты, отличная документация API | нет реактивности/компонентов | 
| Jinja2 (SSR) | проще SEO, меньше JS | дублирование логики шаблонов и API | позже, если понадобится SEO |
| Vue/React + FastAPI | компоненты, экосистема | нужен node + сборка + CI на два стека | когда проект вырастет |

Стек: Python 3.11+, FastAPI, Uvicorn, Pydantic, pytest, ruff, Docker, GitHub Actions.

---

## 2. Слои и правило зависимостей

```
Запрос → routes (тонкий)  → services (логика)  → data/БД
                ↓
            schemas (контракт, Pydantic)
```

* **routes** — только HTTP: принять, проверить, позвать сервис, вернуть схему.
* **services** — логика и доступ к данным. Здесь живёт вся «настоящая» работа.
* **schemas** — контракт API. Одна схема = одна форма ответа/запроса.
* **core/config** — пути и настройки из переменных окружения.

**Зависимость только в одну сторону**: routes знает про services и schemas,
services — только про schemas и config. Обратных импортов быть не должно.

## 3. Что где лежит

| Путь | Что это | Комментарий |
|---|---|---|
| `api/app/main.py` | точка входа FastAPI | API + Swagger + раздача SPA |
| `api/app/core/config.py` | настройки | единственное место чтения env |
| `api/app/core/static_files.py` | раздача статики | поиск файла + защита от path traversal |
| `api/app/api/router.py` | сборка роутов | префикс `/api` |
| `api/app/api/routes/*.py` | роуты по фичам | 1 файл = 1 фича |
| `api/app/schemas/*.py` | Pydantic-схемы | контракт API |
| `api/app/services/*.py` | логика, доступ к данным | сейчас JSON, позже БД |
| `api/app/data/*.json` | заглушки данных | заменить на БД в задаче 05 |
| `frontend/index.html` | каркас SPA | шапка, меню, `<main id="app">`, подвал |
| `frontend/pages/*.html` | разметка страниц | грузится роутером, без `<html>` |
| `frontend/js/main.js` | общая логика | единственный способ звать API (`apiGet`) |
| `frontend/js/router.js` | роутер SPA | сюда добавляем новые страницы |
| `frontend/js/pages/*.js` | логика страницы | функция `init<Имя>()` |
| `frontend/css/base.css` | общие стили | CSS-переменные, каркас |
| `frontend/css/components/` | переиспользуемые стили | кнопки, карточки, формы |
| `frontend/css/pages/` | стили страниц | одна страница = один файл |
| `tests/test_*.py` | тесты pytest | 1 файл фичи = 1 файл тестов |
| `tests/test_static_files.py` | unit-тесты без FastAPI | чистая логика раздачи статики |
| `tests/test_frontend_wiring.py` | проверка связки SPA | пути, страницы, обработчики |
| `docs/tasks/*.md` | задания участникам | каждый берёт один файл |

## 4. Как выглядит «фича» (вертикальный срез)

Фича = сквозная цепочка от данных до картинки в браузере:

```
data/БД → services/ → schemas/ → routes/ → tests/ → frontend/pages + js/pages
```

Эталон — фича «Информация о кафедре» (`GET /api/department`):

| Слой | Файл |
|---|---|
| данные | `api/app/data/department.json` |
| схема | `api/app/schemas/department.py` |
| логика | `api/app/services/department.py` |
| роут | `api/app/api/routes/department.py` |
| монтаж | `api/app/api/router.py` |
| тест | `tests/test_department.py` |
| фронтенд | `frontend/pages/home.html` + `frontend/js/pages/home.js` |

Порядок работы над любой задачей: **фича маленьким куском + тест к ней + PR**.
Не «весь API за один раз», а один endpoint за один коммит.

---

## 5. Правила, которые нельзя нарушать

1. Всякий ответ API описан Pydantic-схемой (`response_model=`).
2. Роут не содержит логики и не ходит в файлы/БД напрямую.
3. Настройки и секреты — только через переменные окружения.
4. Новый код без теста не принимается (см. `docs/CONVENTIONS.md`).
5. Неизвестный `/api/**` возвращает JSON-404, а не HTML (проверяется тестом).
6. Фронтенд не дублирует бизнес-логику: считает и решает бэкенд.
