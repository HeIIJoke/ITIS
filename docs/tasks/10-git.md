# Задача 10. Git-практикум: ветки, PR, конфликты

**Ветка:** своя для каждого пункта · **Зависимости:** нет · **Инструменты:** git, pre-commit, GitHub

## Чему учимся
Работать в команде: ветки, PR, ревью, разрешение конфликтов, откат ошибок,
гигиена репозитория. Расширяем и дополняем `docs/CONVENTIONS.md`.

## Задания (по одному PR на каждое)
1. **Ветки и PR**: создай `feature/...`, сделай 2–3 осмысленных коммита
   (Conventional Commits), открой PR по шаблону, получи approve, смержи.
   Затем удали ветку локально и на remote.
2. **Конфликт руками**: вместе с коллегой правьте один и тот же файл
   (например `frontend/js/router.js`). Разреши конфликт, объясни в PR,
   почему выбрал именно такое слияние.
3. **Rebase vs merge**: приведи свою ветку в актуальное состояние двумя способами,
   сравни историю (`git log --graph --oneline`), опиши выводы в PR.
4. **Откат ошибок**: 
   * `git restore <file>` — выкинуть незакоммиченное;
   * `git revert <sha>` — отменить уже запушенный коммит;
   * `git reset --soft/--mixed` — переписать локальную историю;
   * `git reflog` — найти «потерянный» коммит. Покажи в PR вывод команд.
5. **Cherry-pick и stash**: перенеси один фикс в другую ветку через `git cherry-pick`;
   используй `git stash` для переключения контекста и верни изменения обратно.
6. **Гигиена**: слияние `develop` в `main` только через PR; `.gitignore`
   покрывает кэши/секреты (проверь `git status` на чистоте); удали из истории
   случайно закоммиченный файл (`git rm --cached`, а секрет — сменой значения!).
7. **Автоматизация**: подключи `pre-commit` с хуками `ruff`, `ruff-format`,
   `end-of-file-fixer`, `check-yaml`. Конфиг — `.pre-commit-config.yaml`, запуск
   `pre-commit install`. Хук должен падать на плохом форматировании.
8. **Подписанные коммиты** (бонус): настрой GPG/SSH-подпись, включи
   «Require signed commits» на `main`. Покажи `git log --show-signature`.

## Подсказки
* Перед любым rebase сделай `git switch -c backup/<ветка>` — страховка.
* Конфликт решается в редакторе, а не «угадыванием»: смотри обе версии.
* `git push --force-with-lease` вместо `--force` (не затрёт чужую работу).
* Никогда не `rebase`/`amend` то, что уже смержено в `develop`.

## Definition of Done
- [ ] Все 8 пунктов выполнены, каждый — отдельным PR со ссылкой на вывод команд
- [ ] Конфликт разрешён без потери чужих изменений
- [ ] `pre-commit` установлен и реально блокирует плохой коммит
- [ ] В `docs/CONVENTIONS.md` добавлены возникшие договорённости
