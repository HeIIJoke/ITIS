# Задача 04. Научная работа и публикации

**Ветка:** `feature/science` · **Зависимости:** нет · **Инструменты:** FastAPI, Pydantic, pytest

## Чему учимся
Связи между сущностями (преподаватель ↔ публикация), агрегация и статистика,
сложные схемы ответа, построение комбинированных фильтров.

## Контракт API
| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/science/publications` | `?year=&type=&teacher_slug=&q=` |
| GET | `/api/science/stats` | агрегаты: всего, по годам, по типам |
| GET | `/api/science/teachers/{slug}/publications` | публикации конкретного преподавателя |

Публикация: `id`, `title`, `authors` (список), `year`, `type`
(статья/тезисы/монография/РИД), `journal`, `link`, `doi`.

## План работы
1. Схемы `schemas/science.py`: `Publication`, `PublicationType` (Enum), `ScienceStats`.
2. Данные `data/publications.json` — 15+ записей, привязанных к slug преподавателей
   из задачи 01 (если она уже в `develop`; иначе создай свои slug-и).
3. Сервис: фильтры, сортировка по году вниз, функция агрегации `build_stats()`.
4. Тесты: `q` ищет по названию; фильтр по году сужает список; `stats.total`
   равен длине общего списка; пустой результат — `200` и `[]`, не `404`.
5. Фронтенд: страница «Наука», таблица публикаций + карточки статистики.

## Подсказки
* Пустой список — это **не** ошибка: всегда `200` и `[]`.
* Агрегаты считай на бэкенде (`Counter` из `collections`) — не в JS.
* Подумай про будущую БД: сервис уже сейчас должен возвращать данные,
  не завися от JSON-файла (сигнатура без путей).
