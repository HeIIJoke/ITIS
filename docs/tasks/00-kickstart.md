# Задача 00. Стартовая фича + тест (эталон)

**Статус: уже реализовано** — читаем код и повторяем схему в своей задаче.

## Чему учимся
Сквозной цикл «фича + тест»: данные → сервис → схема → роут → тест → фронтенд.

## Что уже сделано
| Слой | Файл |
|---|---|
| данные | `api/app/data/department.json` |
| схема | `api/app/schemas/department.py` |
| логика | `api/app/services/department.py` |
| роут | `api/app/api/routes/department.py` (+ `api/app/api/router.py`) |
| тест | `tests/test_department.py` |
| фронтенд | `frontend/pages/home.html` + `frontend/js/pages/home.js` |

## Задание
1. Запусти всё локально и убедись, что работает:
   ```bash
   make install
   make dev            # http://localhost:8080  и  /api/docs
   make test
   ```
2. Прочитай файлы из таблицы по порядку — это шаблон для твоей задачи.
3. Сломай фичу (убери поле из `department.json`) и посмотри, **какой тест упал**.
   Верни как было. Это и есть смысл теста.
4. Упражнения по возрастанию сложности:
   * добавь в схему поле `site_url` и выведи его на главной;
   * добавь эндпоинт `GET /api/department/contacts` (отдельная схема `DepartmentContacts`);
   * добавь негативный тест: если `email` пустой — `GET /api/department` отдаёт 500
     (это баг! подумай, как отдавать 503 с понятным сообщением).

## Definition of Done
- [ ] `make dev` поднимает сайт, главная отображает данные из API
- [ ] `make test` и `make lint` зелёные
- [ ] Упражнение из п. 4 сделано и покрыто тестом
