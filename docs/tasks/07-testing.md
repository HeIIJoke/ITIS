# Задача 07. Тестирование: пирамида и качество

**Ветка:** `feature/testing` · **Зависимости:** любые готовые фичи
**Инструменты:** pytest, pytest-cov, параметризация, фикстуры, Playwright (e2e)

## Чему учимся
Строить пирамиду тестов, измерять покрытие, изолировать тесты, тестировать
не только API, но и реальный браузер.

## Пирамида
```
        / e2e (2-3 сценария)  \      Playwright: открыл сайт, увидел данные
      / интеграционные API     \    TestClient: роут + сервис + валидация
    /   unit (много, быстрые)    \  чистые функции, валидаторы, фильтры
```

## План работы
1. **Покрытие**: `pyproject.toml` уже настроен; добейся `--cov-fail-under=60` минимум,
   затем подними до 85. Отчёт HTML: `pytest --cov-report=html`.
2. **Параметризация**: один тест — много кейсов
   (`@pytest.mark.parametrize` для фильтров, кодов ошибок, форматов времени).
3. **Фикстуры**: вынеси подготовку данных в `tests/conftest.py`, добавь фабрики
   (`make_teacher(**overrides)`) вместо копипаста словарей.
4. **Негативные и граничные кейсы**: пустые значения, огромный `limit`, спецсимволы,
   `limit=0`, отрицательный `offset`, отсутствующие поля, дубликаты.
5. **Маркеры**: `@pytest.mark.slow` для медленных тестов, запуск `pytest -m "not slow"`.
6. **E2E (Playwright)**: отдельная папка `tests/e2e/`, сценарии:
   * главная открывается и показывает название кафедры из API;
   * переход между разделами SPA-роутером без перезагрузки (проверить URL);
   * создание новости через форму (если задача 03 готова).
   Playwright поднимает `uvicorn` в фикстуре, в CI — headless.
7. **Мутационная проверка вручную**: сломай код, убедись, что тест падает,
   верни код. Тест, который не падает — бесполезен.

## Подсказки
* Тесты не зависят от порядка: ни один тест не оставляет данные для другого.
* Не тестируй фреймворк: не проверяй, что FastAPI умеет 422 — проверяй свою схему.
* `tmp_path` — встроенная фикстура для временных файлов, не пиши в `api/app/data`.
* E2E не должен дублировать API-тесты: там проверяем только связку UI ↔ API.
