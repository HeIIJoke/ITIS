# Задача 02. Расписание

**Ветка:** `feature/schedule` · **Зависимости:** нет · **Инструменты:** FastAPI, Pydantic (валидация), pytest

## Чему учимся
Моделировать «сложные» данные (вложенные структуры), валидировать форматы
(день недели, время), отдавать данные по фильтрам, строить таблицу на клиенте.

## Контракт API
| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/schedule` | всё расписание; фильтры `?group=`, `?teacher=`, `?day=` |
| GET | `/api/schedule/lessons/{lesson_id}` | одна пара; 404 если нет |

Модель пары: `id`, `day` (Пн…Сб), `time_start`/`time_end` (`HH:MM`), `subject`,
`group`, `teacher`, `room`, `kind` (лекция/практика/лаборатория).

## План работы
1. Схемы `api/app/schemas/schedule.py`: `Lesson`, `LessonKinds` (Enum!), валидация
   времени через `field_validator` — `time_end` должен быть позже `time_start`.
2. Данные: `api/app/data/schedule.json` (10–20 пар, 2–3 группы).
3. Сервис `services/schedule.py`: фильтры по группе/преподавателю/дню, сортировка по времени.
4. Роуты + тесты (`tests/test_schedule.py`): фильтр по группе, неверный день → 422,
   пары отсортированы по времени, у пары есть преподаватель.
5. Фронтенд: страница «Расписание» (новый роут в `router.js`), таблица «день × пары»,
   переключатель группы. Стили — `frontend/css/pages/schedule.css`.

## Подсказки
* `Enum` в Pydantic сам даёт 422 на неизвестный вид занятия — бесплатная валидация.
* День недели лучше тоже сделать `Enum("Пн", ...)` — тогда `?day=Понедельник` даст 422.
* Не считай «текущую пару» на клиенте — отдай с бэкенда поля `is_now`/`order`.

## Definition of Done
- [ ] API отдаёт расписание с рабочими фильтрами и валидацией
- [ ] Тесты покрывают фильтры, сортировку и ошибки валидации
- [ ] Страница отображает таблицу, переключение группы работает без перезагрузки
